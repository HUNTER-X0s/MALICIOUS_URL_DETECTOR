# SEO and discoverability requirements

## Website SEO
- Make only intended public marketing, documentation and educational pages crawlable and indexable.
- Keep private scan results, account pages, user-submitted content, tokens and sensitive URLs out of indexes. Use authentication, noindex/robots/canonical rules appropriately; robots.txt is not access control.
- Research search intent and build genuinely useful, original content: phishing education, URL safety guidance, threat explainers, product documentation and transparent methodology where disclosure does not aid evasion.
- Use semantic HTML, descriptive titles/meta descriptions, canonical URLs, clean information architecture, internal links, sitemap, robots directives, structured data only when valid, accessible content and performant rendering.
- Monitor crawl/index coverage, query performance, Core Web Vitals and structured-data warnings through official webmaster tools where authorized.
- Avoid keyword stuffing, doorway pages, scaled low-value AI content, fake reviews, misleading claims, link schemes and fabricated trust signals.
- No guarantee of top ranking. SEO is a continuous product/content discipline, not a development-only setting.

## Extension discovery
Extension listings are separate from search-engine SEO. Optimize listing clarity, accurate title/description, permissions disclosure, privacy declarations, screenshots and support. Follow each store's current review and keyword policies. Never misrepresent capabilities or ask for broad permissions only to appear more useful.

## Security constraints
Never publish scan result pages or user-provided URLs as indexable public content by default. Do not leak submitted URL tokens through referrers, analytics, page titles, canonical URLs or public share links.
