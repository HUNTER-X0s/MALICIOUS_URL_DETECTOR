# Requirements seed (not a final SRS)

## Functional capability areas
- Parse and safely normalize submitted URLs without visiting them.
- Return a versioned verdict contract with evidence, confidence, freshness, limitations and suggested action.
- Layer local lexical/structural signals with licensed reputation, domain/DNS/TLS, redirects and optional isolated page inspection.
- Provide transparent history and privacy controls where accounts are enabled.
- Offer browser protection with understandable states, minimal permissions and graceful offline behavior.
- Offer documented rate-limited developer APIs and API key lifecycle controls.
- Administer sources, rules, feedback, incidents and abuse with auditability.

## Non-functional requirements
Security, privacy, availability, data integrity, observability, accessibility, performance, portability, maintainability, disaster recovery, cost control, legal compliance and interoperability.

## Requirements process
Antigravity must conduct user interviews/surveys where possible, competitor review, abuse-case discovery and feasibility assessment. Each requirement must have ID, rationale, source, priority, owner, dependencies, privacy/security impact, acceptance test and release scope. This seed does not authorize implementation without analysis.
