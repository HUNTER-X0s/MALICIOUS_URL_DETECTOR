# Test verification

Map requirements to tests and evidence. Select appropriate unit, component, integration, contract, API, E2E, regression, smoke, compatibility, extension, accessibility, visual, performance, load, stress, soak, chaos/resilience, fuzz, property-based, adversarial, privacy and security tests. Use isolated labs and synthetic fixtures. Avoid uncontrolled scanning of real sites. Record tool versions, environment, commands, pass/fail, skipped cases, defects and evidence paths. Verify bug fixes with regression tests. Do not claim tests passed unless actually run.
